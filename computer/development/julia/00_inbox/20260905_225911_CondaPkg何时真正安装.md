# CondaPkg 何时真正安装

**日期**: 2026-09-05 22:59
**分类**: 编程/Julia
**标签**: #CondaPkg #版本管理

## 背景

包里写了 `CondaPkg.toml` 并进了依赖，`Pkg.add` 后 Python 依赖却没装上，查源码（CondaPkg 0.2.33）确认触发规则。

## 手动触发（装好后一劳永逸）

```julia
using CondaPkg
CondaPkg.resolve()
```

- 解析时会扫整个调用链，把链上所有包的 `CondaPkg.toml` 合并安装；在哪个项目环境里执行，就装进哪个环境。
- `Pkg.add` 只装 Julia 部分；`using` 你的包也不会装，除非包里自己调了（包设计见下）。

## 自动触发的接口

```julia
CondaPkg.which("python")
CondaPkg.envdir()
CondaPkg.withenv() do
    run(`python ...`)
end
# pkg> conda run python ...   # 同样自动触发
```

- 调用链：`withenv` 经 `activate!` 走到 `envdir` 再到 `resolve`；`which` 经 `bindirs` 走到 `envdir` 再到 `resolve`；`conda run` 经 `withenv`，一样。
- 主模块里没有自动解析，唯一的初始化只注册 REPL 命令，也没有装包钩子。

## 包设计取舍

```julia
# 包本体用不到 Python（如只给外部脚本用）：别放初始化里强制装，
# 提供按需函数让用户自己调，避免纯 Julia 用户被迫下载全套
function install_python_deps()
    CondaPkg.resolve()
    println("Python environment: ", CondaPkg.envdir())
end
```

## 要点

- 配置文件只是声明，动手的永远是解析那一下，直接调或经上面接口间接调。
- 想推 Python 依赖更新就换声明里的钉住号，用户照常升级包即跟上（见笔记《CondaPkg 的 Python 依赖管理》）。
