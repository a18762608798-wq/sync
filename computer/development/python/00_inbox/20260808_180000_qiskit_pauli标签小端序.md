# Qiskit Pauli 标签的小端序惯例

**日期**: 2026-08-08
**分类**: 编程/Python
**标签**: #qiskit #pauli #quantum_computing

## 背景

在 `qmeas` 项目中编写 `QubitwiseBasis.recover()` 的测试时，发现 `Pauli("IX")` 的实际含义与直觉相反，导致断言失败。

## 内容

Qiskit 中 `Pauli` 和 `PauliList` 的字符串标签采用**小端序（little-endian）**：右侧字符对应 qubit 0，左侧对应 qubit N-1。

- `"IX"` → X 在 q0，I 在 q1
- `"XI"` → I 在 q0，X 在 q1
- `"XX"` → X 在 q0，X 在 q1

```python
from qiskit.quantum_info import Pauli
p = Pauli("IX")
print(p.x)  # array([ True, False])  → q0 有 X
print(p.z)  # array([False, False])  → 都没有 Z
```

所以 `Pauli("XI")` 才是 X 在 qubit 1。与直觉相反——直觉上 "X" 在前面会想到 q0。

在构建 mask 做奇偶校验时需注意：`enumerate(support)` 的 index 0 对应 q0，与字符串的右侧字符一致。

## 要点

- Qiskit Pauli 标签是小端序：右侧 = q0
- 构建 bitmask 时 `1 << i` 对应 qubit i，与 `int(bitstring, 2)` 的 bit i 一致（前提是 bitstring 也是小端序）
- 写测试时不要凭直觉假设标签顺序，用 `pauli.x` / `pauli.z` 直接检查
