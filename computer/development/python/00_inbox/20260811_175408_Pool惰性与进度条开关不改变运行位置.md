# multiprocessing.Pool 惰性执行与进度条开关

**日期**: 2026-08-11 17:54
**分类**: 编程/Python
**标签**: #Python #multiprocessing #Pool #imap #tqdm #多进程

## 背景

用 `multiprocessing.Pool` + `imap` 并行跑一组优化任务，并给进度条（tqdm）加开关。需要理清任务真正执行的位置，以及进度条开关对运行位置的影响。

## 内容

### 1. pool.imap 是惰性的

```python
iterable = pool.imap(_wrapper, tasks)   # 只是返回迭代器，此时尚未执行任何任务
```

`imap` 返回一个**惰性迭代器**，此刻没有任何任务被真正执行。真正的执行发生在**主进程消费这个迭代器**时（如 `list(iterable)`）。

### 2. 任务始终在子进程运行

任务（`_wrapper` → 实际业务函数）始终在 `Pool(processes=n)` 创建的 **n 个子进程**里并行执行。进度条开关只决定主进程取结果时**是否显示进度条**，不影响运行位置：

```python
with Pool(processes=8) as pool:
    iterable = pool.imap(_wrapper, tasks)
    if progress:
        iterable = tqdm(iterable, total=len(tasks))   # 包一层进度条
    results = list(iterable)                          # 此时才真正执行
```

- `progress=False`：`list(iterable)` 逐个取结果，子进程并行执行，无进度显示
- `progress=True`：tqdm 在**主进程**逐项更新进度条，任务仍跑在子进程

两种情况下任务执行位置、性能完全一致，区别仅在进度条显示。

### 3. 多进程共享可变对象的坑

不要用 `itertools.repeat(history)` 把**同一个可变对象**（如 list）传给多个并行任务。多进程 fork 后各自是拷贝、互不可见，且写入同一列表有数据竞争风险。每个任务应传独立对象：

```python
# _wrapper 内部 history=[]  每个任务独立列表
```

## 要点

- `imap` 惰性返回迭代器，任务在消费迭代器时才执行
- `progress` 开关不改变任务运行位置（始终在子进程），只控制进度条显示
- 并行任务不要共享同一个可变对象，用独立对象
