# raise 与 assert 的区别与使用位置

**日期**: 2026-08-04 15:16
**分类**: 编程/Python
**标签**: #Python #异常 #assert #调试

## 背景

讨论 Python 中 `raise` 与 `assert` 的区别，以及异常检查应该放在笔记/代码的什么位置。

## 内容

### 语义对比

- **`raise`**：主动报错。程序运行到该句**一定会抛异常**，表达"这里出错了，不能继续"。针对**可预期、已考虑到的错误**（参数校验、业务规则：余额不足、文件不存在、网络失败），通常配套 `try/except` 分支处理。
- **`assert`**：断言/假设检查。检查条件，成立继续，不成立抛 `AssertionError`。针对**意外、不该发生的情况**（内部逻辑不变量），失败说明代码有 bug，目的是尽早暴露 bug，一般**不捕获**，让它崩。

### 关键差异表

| | raise | assert |
|---|---|---|
| 语义 | 主动报告错误 | 验证假设成立 |
| 针对 | 外部输入/运行时情况 | 内部逻辑 bug |
| `python -O` 下 | 仍生效 | **被移除** |
| 能否被 except | 能，且应主动设计 | 能，但一般不该捕获 |

### 判据

**这条检查在 `python -O` 下失效会不会出问题？**
- 会 → 用 `raise`（外部输入永远用 `raise` 而非 `assert`）
- 不会（纯防御性验证）→ 用 `assert`

### 代码示例

```python
# raise：函数入口做参数校验（guard clause）
def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("余额不足")
    return balance - amount

# assert：验证内部不变量（逻辑上不该失败）
def compute(x):
    result = x * 2
    assert result > 0, "结果应为正数"
    return result
```

- 建议优先使用内置异常类型（`ValueError`、`TypeError`、`KeyError`、`FileNotFoundError` 等），别一律用 `Exception`，调用方才好 `except` 捕获。

## 要点

- `raise` 用于可预期的错误并主动设计 except 分支；`assert` 用于不该发生的意外情况，让它崩掉以暴露 bug。
- 唯一判据：`python -O` 下失效是否出问题，出问题用 `raise`。
- `assert` 会随 `-O` 被移除、可用 `except AssertionError` 吞掉，所以绝不能用作对外输入校验。
