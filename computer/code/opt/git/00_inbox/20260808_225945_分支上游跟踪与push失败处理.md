# Git 分支上游跟踪与 git push 失败处理

**日期**: 2026-08-08 22:59
**分类**: 工具/Git
**标签**: #Git #push #upstream #分支合并

## 背景

在分支 `feature/estimator` 上直接执行 `git push` 报错"当前分支没有对应的上游分支"，随后将分支合入 master 并删除。涉及分支上游跟踪、push 失败处理、分支合并与清理的完整流程。

## 内容

### 1. 直接 push 失败的原因

`git push` 不带参数时，git 需要知道"推送到哪个远程的哪个分支"。如果本地分支没有设置上游跟踪分支（upstream），git 无法确定目标，报错：

```
fatal: 当前分支 feature/estimator 没有对应的上游分支。
```

这不是分支名的问题，而是分支缺少上游关联。新创建的分支默认没有上游。

### 2. 解决办法

```bash
# 推送并同时建立上游跟踪（一次性操作，之后可直接 git push）
git push --set-upstream origin feature/estimator
# 简写
git push -u origin feature/estimator

# 或全局配置自动设置上游：以后新分支直接 git push 即可
git config --global push.autoSetupRemote true
```

查看分支上游关联状态：

```bash
git branch -vv        # 显示每个分支的上游跟踪分支
```

### 3. 将分支合入 master 并删除分支

```bash
git checkout master                 # 切到目标分支
git merge feature/estimator --no-edit  # 合并（--no-edit 使用默认合并信息）
git push                            # 推送 master
git branch -d feature/estimator     # 删除本地分支
git push origin --delete feature/estimator  # 删除远程分支
```

master 没有新提交时合并是 fast-forward（快进），不会产生合并提交。

## 要点

- `git push` 失败提示"没有上游分支"时用 `-u` 参数建立跟踪
- `push.autoSetupRemote true` 可让新分支自动建立上游
- `git branch -vv` 查看各分支与上游的关联
- 清理分支需同时删除本地（`branch -d`）和远程（`push origin --delete`）
