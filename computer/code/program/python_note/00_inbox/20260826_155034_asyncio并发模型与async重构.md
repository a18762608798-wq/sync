# asyncio 并发心智模型与 async 重构模式

**日期**: 2026-08-26 15:50
**分类**: 编程/Python
**标签**: #asyncio #异步 #并发 #设计模式

## 背景

重构量子计算项目的 ZNE 采样链路（`get_cost_val` → `get_ZNE_vals`），把串行的 n 个噪声放大级采样改为并发提交（quark 云端 I/O 密集，本地 aer 为 C++ 计算）。过程中厘清了 asyncio 的三个核心概念和一套可复用的「sync/async 双层 API」重构模式。

## 内容

### 三个动作的心智模型

```python
import asyncio

async def f():
    await asyncio.sleep(1)
    return 1

f()                          # 1. 只创建协程对象, 什么都不执行
t = asyncio.create_task(f()) # 2. 派发: 挂到循环上, 立即返回句柄
await f()                    # 3. 内联执行: f 挂起时我也挂起, 控制权回循环
asyncio.run(f())             # 4. 执行器: 新建循环+阻塞当前线程跑完+关循环
```

- **`await` 不是派发**，是「内联执行 + 挂起传播」：被 await 的协程在第一个挂起点停住时，当前协程一起停住，循环转去跑别的任务。
- 并发来自 `gather`/`create_task`（派发）与 await 链（让出）的组合。

### 并发生效的条件：等待期必须 await 让出

```python
async def bad():
    return time.sleep(2)   # 标了 async 但一个 await 都没有

# gather 十个 bad() 照样串行, 还各自阻塞整个循环
```

判断标准不是"函数标了 async"，而是**真正的耗时阶段（等待期）有没有 await 让出**。qmeas 的 `_run_quark` 在轮询里 `await asyncio.sleep(10)` → 可并发；`_run_aer` 内部全程同步 `job.result()` → 标了 async 也白搭。

### 阻塞调用用 asyncio.to_thread 包住

```python
async def get_cost_val_async(qc, op, *, chip="qiskit_aer", chip_options=None):
    if chip == "qiskit_aer":
        # C++ 模拟释放 GIL, 丢进线程池不卡循环
        return await asyncio.to_thread(get_cost_val_by_qiskit_aer, qc, op)
    result = await run_estimator(config)   # I/O 密集: 直接 await
```

### sync/async 双层 API 重构模式

原则：**中间只 await，入口 run 一次，并发靠 gather**。

```python
# 同步薄包装: 给不想碰 async 的调用方(objective、测试)
def get_cost_val(qc, op, *, chip="qiskit_aer", chip_options=None):
    return asyncio.run(
        get_cost_val_async(qc, op, chip=chip, chip_options=chip_options)
    )

# 并发层: 把所有 n 同时派发
async def get_ZNE_vals(s, n_list, θodd, θeven, ...):
    vals = await asyncio.gather(
        *(get_ZNE_val(s, n, θodd, θeven, ...) for n in n_list)
    )
    return [2 * n + 1 for n in n_list], list(vals)

# 入口: 全程序只有一次 asyncio.run
if __name__ == "__main__":
    asyncio.run(main())
```

约束：sync 包装内部就是 `asyncio.run`，**只能在 sync 上下文调用**，绝不能出现在运行中的事件循环里；async 版只能在 async 上下文 `await`。两层各归各的，不能混用。

### 并发提交时任务名加后缀防撞名

多个任务共用同一份 `chip_options` 并发提交时，按来源和序号区分名字，方便平台上追踪：

```python
opts = dict(chip_options)
opts["name"] = f"gs_{opts.get('name', 'my_job')}_n{n}"
```

## 要点

- `f()` 创建协程、`create_task` 派发、`await` 内联执行+挂起传播、`asyncio.run` 同步执行器入口。
- 并发生效看"等待期是否 await 让出"，不看函数是否标 async。
- 阻塞计算（GIL 释放的 C++）用 `asyncio.to_thread`，I/O 协程直接 `await`。
- 重构模式：async 链贯穿到底，入口 `asyncio.run` 一次，中间 `gather` 并发；同步调用方用 `asyncio.run(async 版)` 薄包装。
