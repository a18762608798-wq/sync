# JSON 读写后字典键变成字符串 & 模块导入执行顶层代码

**日期**: 2026-08-12 14:18
**分类**: 编程/Python
**标签**: #python #json #调试 #模块导入 #坑

## 背景

在量子变分参数优化的脚本中，先用 `json.dump` 把 `optimize_pipeline` 返回的字典存盘，再用 `json.load` 读回作为下一阶段的初值 `t0`。运行时出现 `KeyError: 0`，排查发现是 JSON 读写改变了字典的键类型。

## 内容

### 1. JSON 读回后字典键全部变成字符串

`optimize_pipeline` 返回以整数为键的字典（`{0: {...}, 1: {...}, ...}`）。但 JSON 的键只能是字符串：

```python
# 存盘前（原始 dict，键是 int）
d = {0: {"res": {"t": [0.5]}}, 1: {"res": {"t": [0.6]}}}

# dump 再 load
import json
s = json.dumps(d)
d2 = json.loads(s)          # 键变成 '0'、'1'（str）
list(d2.keys())             # ['0', '1']
d2[0]                       # KeyError: 0
```

因此用整数索引 `d2[i]` 会 `KeyError`。**解决**：不要用 `range(len(d))` + 整数下标，改用遍历键：

```python
t0 = [d2[k]["res"]["t"] for k in d2]   # k 是字符串键
```

**经验规律**：同一个 `result_dic[i]` 写法，`result_dic` 是原始返回（int 键）时能跑，一旦经过 JSON 读写再读回（str 键）就会报 `KeyError`。凡是「字典先 dump 再 load」的代码，遍历时一律按 `for k in d` 处理。

### 2. `from module import NAME` 会执行模块的整个顶层代码

`from save_aer_spectrum import END` 会把 `save_aer_spectrum` 模块**从头到尾完整执行一遍**，包括顶层所有 `import` 语句，之后才返回 `END`。

`if __name__ == "__main__"` 只能挡住主程序块，**挡不住顶层的 import**：

```python
# save_aer_spectrum.py
from qiskit_algorithms.optimizers import SPSA, DIRECT_L  # 顶层 import，import 本模块时必执行

END = [0.5, 0.3]

if __name__ == "__main__":
    ...  # 这段不会在被 import 时执行（__name__ != "__main__"）
```

所以被 `from ... import` 引入时，仍会连带加载 qiskit 等依赖。若只想复用常量，更干净的做法是**在目标文件里本地重新定义**，避免模块间隐式依赖。

## 要点

- JSON 的键只能是字符串，`json.load` 后字典键（原为 int）会变 str，`d2[i]`（int 下标）报 `KeyError`。
- 遍历经过 JSON 往返的字典，统一用 `for k in d`，不要用 `range(len(d))` 整数下标。
- `from module import X` 会执行该模块全部顶层代码（含顶层 import），`if __name__` 只保护主程序块。
- 跨脚本复用简单常量时，倾向直接本地定义，而不是从一个可执行脚本里 import。
