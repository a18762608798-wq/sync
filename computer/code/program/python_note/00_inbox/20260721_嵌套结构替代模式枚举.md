# 用自描述嵌套结构替代模式枚举

**日期**: 2026-07-21
**分类**: 编程/Python
**标签**: #design-pattern #typing #refactoring #dataclass

## 背景

`qmeas` 项目中，`RandomMeasConfig` 原来通过 `meas_mode: Literal["independence", "pair"]` 决定 `meas_indices: list[int]` 中相邻 qubit 是否共享测量旋转门参数。这导致两个问题：

1. 用户必须按计算逻辑手动排列 `meas_indices` 顺序
2. 后处理需要依赖 `meas_mode` 才能正确解析 `meas_indices` 的语义

## 内容

将 `meas_indices: list[int]` 改为 `meas_indices: list[tuple[int, ...]]`，每个 tuple 内的 qubit 共享同一组测量参数。`meas_mode` 字段被完全删除。

```python
# 旧：mode 隐式定义分组
meas_indices = [2, 5, 3, 4]  # 只能靠文档约定 [2,5] 一对, [3,4] 一对
meas_mode = "pair"

# 新：结构直接表达分组
meas_indices = [(2, 5), (3, 4)]  # 显式分组
```

连带简化：
- 删除了 `GROUP_BUILDERS`、`_independent_groups`、`_paired_groups`、`_expand_group_values`（~60 行）
- `ParameterGenerator.generate()` 不再需要接受 `meas_indices` 参数
- `add_meas()` 改为遍历 tuple groups，组内 qubit 施加相同参数

类型注解使用 `list[tuple[int, ...]]`，其中 `...` 表示可变长元组。

JSON 序列化天然支持：`json.dump` 将 `list[tuple]` 输出为 `list[list]`，零转换开销。

## 要点

- 当 mode/enum 字段的唯一作用是改变 flat list 的解释方式时，考虑将解释规则直接嵌入数据结构
- 嵌套结构 = 自文档化，消除 post-processing 的分支判断
- `list[tuple[int, ...]]` 表达可变长元组列表，适用于分组但组内元素数量可变的场景
- 删除 `group_builder` 类基础设施后，分组逻辑从参数生成层下移到电路构造层（`add_meas`），更贴近物理语义
