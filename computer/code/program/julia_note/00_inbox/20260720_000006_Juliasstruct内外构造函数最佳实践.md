# Julia struct 内/外构造函数最佳实践

**日期**: 2026-07-20 20:30
**分类**: 编程/Julia
**标签**: #Julia #struct #构造函数 #类型

## 背景

讨论 QMeasPost 项目中 `load_randmeas_result` 这样的函数是否应该放在 `struct` 内部时，引出了 Julia 构造函数设计的核心问题：inner constructor 与 outer constructor 的区别和最佳实践。

## 内容

### Julia struct 的方法限制

Julia 的 `struct` 只能定义字段数据，**不能包含普通方法**——唯一能写在 `struct` 内部的是 **inner constructor**（内部构造函数）。

```julia
# struct 只放数据 + 内部构造函数
struct FactorizedShadow <: AbstractShadow
    shadow_data::Vector{ITensor}
    N::Int
    site_indices::Vector{Index{Int64}}

    # 唯一能放在 struct 内部的方法：inner constructor
    function FactorizedShadow(shadow_data, N, site_indices)
        @assert length(shadow_data) == N
        # ... 校验 ...
        new(shadow_data, N, site_indices)  # 调用 new() 创建实例
    end
end

# 普通方法全部在外部
Base.show(io::IO, fs::FactorizedShadow) = ...
```

### 三种构造函数对比

| 类型 | 位置 | 特点 | 何时用 |
|------|------|------|--------|
| **Inner constructor** | `struct` 内部 | 调用 `new()` 创建对象，可做验证/转换 | **最少使用**，只在需要强制不变量时 |
| **Outer constructor** | `struct` 外部 | 调用 inner constructor 的便利包装，不能访问 `new()` | 提供默认值、类型转换 |
| **普通方法** | `struct` 外部 | 操作已有实例 | 所有非构造逻辑 |

### Julia 官方最佳实践

> 尽量少写 inner constructor——只做必要的参数校验和不变量强制。便利构造（默认值、类型转换等）写成 outer constructor。

```julia
struct OrderedPair
    x::Real
    y::Real
    # inner: 仅做强制校验
    OrderedPair(x, y) = x > y ? error("out of order") : new(x, y)
end

# outer: 便利构造
OrderedPair(x) = OrderedPair(x, x)       # 单参数
OrderedPair() = OrderedPair(0.0, 0.0)    # 默认值
```

### 本项目的正确做法

`load_randmeas_result` 放在 `struct` 外部是正确的，因为它：
- 不调用 `new()`，只是从文件反序列化数据
- 本质是一个工厂函数，不是构造器

## 要点

- Julia 与 Python/Java 不同：struct 内不能定义普通方法
- 唯一能放 struct 内的函数是 inner constructor（调用 `new()`）
- 官方推荐：inner 越少越好，只做校验；便利构造放 outer
