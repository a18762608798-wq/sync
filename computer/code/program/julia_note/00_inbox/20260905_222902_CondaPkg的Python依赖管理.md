# CondaPkg 的 Python 依赖管理

**日期**: 2026-09-05 22:29
**分类**: 编程/Julia
**标签**: #CondaPkg #pip #版本管理

## 背景

Julia 包要自带 Python 库，本地开发想用本地文件、别人安装想从云端自动装，由此摸清 CondaPkg 管 Python 依赖的写法与更新机制。

## 从 GitHub 装 pip 包

```toml
[pip.deps.qmeas]
version = "@git+https://github.com/xxx/qmeas.git@b3a2e62d7953df5405ab8dc2e1c38d2ce36b3213"
```

- `@` 是 direct reference 写法（官方文档 FAQ 有），原样传给 pip，所以 `git+https` 地址可用。
- `@` 后面跟标签名或提交号，不写就是裸地址，钉住写这行时云端主分支的样子。
- 本地路径版同理：`version = "@file:///绝对路径/xxx"` 加 `editable = true` 即本地可编辑安装。

## 版本钉住与更新机制

```toml
# 想推更新时，把 @ 后面换成新的标签名或提交号，提交即可
version = "@git+https://github.com/xxx/qmeas.git@v0.2.0"
```

- CondaPkg 只逐字比对这行字：跟上次一字不差就跳过（pip 连网都不连），字变了才重装。所以这串既是版本锁也是更新按钮。
- 裸地址等于冻住首次安装版，云端再提交用户也拿不到；想推就换钉住的号，用户照常更新包即跟上。
- 包本体里的版本号没人看，不用动；钉住用标签名要在仓库打标签，用提交号则去网页提交页面抄，本地推完后 `git log --oneline -1` 最前面那串就是。

## 要点

- 写云端地址，别写本机绝对路径，否则别人装包直接报错（不会忽略）。
- `CondaPkg.toml` 是静态文件，不支持本地一套别人一套的条件写法，本地专用改动靠 git 侧藏（见 git 笔记《用 skip-worktree 藏住本地专用改动》）。
