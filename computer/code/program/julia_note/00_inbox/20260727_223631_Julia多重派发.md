# Julia 多重派发（Multiple Dispatch）

**整理日期**: 2026-07-27
**标签**: #julia #multiple-dispatch #parametric-types #generics #JIT

## 基本概念

多重派发是 Julia 最核心的语言范式。在单派发（single dispatch）语言（如 Python、C++ 的虚函数）中，方法调用仅根据第一个参数（接收者）的类型来选择；Julia 的多重派发则根据**所有位置参数的类型**联合决定调用哪个方法。

Julia 中，函数（function）和方法（method）是分离的：
- **函数**：一个泛化的名称，如 `+`、`push!`、`foo`
- **方法**：函数针对特定类型组合的具体实现

每次调用函数时，Julia 会根据所有参数的具体类型，在方法表中查找最匹配的方法。

```julia
function f(x::Int, y::Int)
    "int-int"
end

function f(x::Int, y::Float64)
    "int-float"
end

function f(x::Float64, y::Int)
    "float-int"
end

f(1, 2)       # "int-int"
f(1, 2.0)     # "int-float"
f(1.0, 2)     # "float-int"
```

在单派发语言中，你无法根据第二个参数的类型来选择不同实现——必须在函数内部手动判断。

## 三种派发方式

### 方式一：具体类型特化（不推荐）

```julia
function simulate(p::Particle{Float64})
    # Float64 专用实现
end

function simulate(p::Particle{Float32})
    # Float32 专用实现（代码重复）
end
```

局限性：每种类型都需单独实现，代码重复。

### 方式二：参数类型泛型（推荐）

```julia
function simulate(p::Particle{T}) where T
    # 适用于任意 T 的泛型实现
    # 编译器会为每个具体 T 生成专门机器码
end

# 另一种等价写法
function simulate(p::Particle{<:Real})
    # 限制 T 为 Real 子类型
end
```

### 方式三：通用实现 + 特化组合

```julia
collide(x, y) = "generic collision"

collide(x::Circle, y::Circle)    = "two circles"
collide(x::Circle, y::Rectangle) = "circle and rect"
collide(x::Rectangle, y::Circle) = "rect and circle"
```

## 方法选择规则

Julia 按以下顺序选择方法：
1. 检查所有方法中参数类型的匹配度
2. 选择最具体（most specific）的匹配——即参数类型更"窄"的那个
3. 如果无法决出唯一最具体的方法，抛出 `MethodError`

## JIT 编译与性能

Julia 的 JIT（Just-In-Time）编译器为每个具体类型组合生成专门的机器码（monomorphization），使得泛型代码无需运行时类型开销，同时提供静态编译语言级别的性能。

调用 `simulate(Particle{Float64}(1.0, 2.0))` 时，编译器自动生成 Float64 版本的机器码；调用 `simulate(Particle{Float32}(1f0, 2f0))` 时，则生成另一份 Float32 版本。

## 注意事项/常见误区

- **类型标注不等于性能优化**：Julia 编译器对 `f(x)` 和 `f(x::Int)` 通常生成相同的机器码（只要能推断出实际类型）。类型标注主要用于**方法派发**，而非性能提示。
- **不要用 Python/C++ 的思维**：在 Julia 中，你应该把"把操作放在它所属的参数组合"上，而不是"把方法挂在类上"。
- **与方法表过多无关的性能影响**：如果方法数量极大，查找开销可能显著，但通常应用中达不到这个量级。
- **泛型代码不牺牲性能**，这是 Julia 高性能的关键设计
- 可用 `where T <: SomeAbstractType` 限制类型范围

## 要点

- 多重派发根据**所有参数**的类型组合决定调用哪个方法
- 使用 `where T` 语法编写参数类型泛型代码，避免为每种类型重复实现
- JIT 编译器自动为具体类型组合生成专用机器码
- 泛型参数类型代码无需手动实例化，编译器自动特化，零运行时抽象开销
