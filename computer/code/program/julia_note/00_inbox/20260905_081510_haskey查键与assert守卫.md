# haskey

**日期**: 2026-09-05 08:15
**分类**: 编程/Julia
**标签**: #julia #dict #haskey #防御性编程

## 背景

给 `RandomMeasAdd` 的 `import_random_group` 加 trivial 校准数据（readout mitigation）兼容时遇到的问题：npz 文件**只有**生成时测了 trivial 数据才带 `trivial_measurement_results` / `trivial_measurement_settings` 键，直接取值会抛 `KeyError`，需要先判断键在不在。

## 内容

`NPZ.npzread` 返回的是普通 `Dict`，用 `haskey` 查键存在性，再配 `@assert` 给出可读报错：

```julia
group_data = npzread(filepath)

if is_mitigation
    @assert haskey(group_data, "trivial_measurement_results") "npz 缺少 trivial_measurement_results：生成该文件时未测 trivial 校准数据，is_mitigation 须为 false"
    @assert haskey(group_data, "trivial_measurement_settings") "npz 缺少 trivial_measurement_settings：生成该文件时未测 trivial 校准数据，is_mitigation 须为 false"
    trivial_meas_res = 2 .- Int64.(group_data["trivial_measurement_results"])
    trivial_settings = ComplexF64.(group_data["trivial_measurement_settings"])
    # ... 构造 MeasurementGroup
end
```

要点：

- `haskey(d, k)` 只查键存在，不取值，无异常开销；对应取值用 `get(d, k, default)`（带默认值）或 `get!`。
- `@assert cond "message"`：条件为假时抛 `AssertionError` 并显示 message，适合守可选输入；正式库代码里更推荐 `throw(ArgumentError("..."))`，断言可能被 `--check-bounds=no` 之类关掉（`@assert` 受 `--compile` 影响小，但语义上仍是调试断言）。
- 同一文件里曾踩过的连带坑：trivial group 构造时误填了非 trivial 的 `meas_res`/`settings`，校准等于没做——凡是"两套同形数据"，构造时逐个核对变量名。

## 要点

- 可选键先 `haskey` 再取值，避免 `KeyError`。
- `@assert` 后跟字符串即自定义报错信息，适合参数合法性守卫。
- 两套同形数据（measurement vs trivial）构造时逐个核对变量，防止串用。
