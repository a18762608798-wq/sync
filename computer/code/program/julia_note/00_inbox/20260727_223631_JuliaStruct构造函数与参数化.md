# Julia Struct 构造函数与参数化类型设计

## Inner vs Outer 构造函数

Julia 的 `struct` 只能定义字段数据，**不能包含普通方法**——唯一能写在 `struct` 内部的是 **inner constructor**（内部构造函数）。

```julia
struct FactorizedShadow <: AbstractShadow
    shadow_data::Vector{ITensor}
    N::Int
    site_indices::Vector{Index{Int64}}

    # 唯一能放在 struct 内部的方法：inner constructor
    function FactorizedShadow(shadow_data, N, site_indices)
        @assert length(shadow_data) == N
        new(shadow_data, N, site_indices)
    end
end

# 普通方法全部在外部
Base.show(io::IO, fs::FactorizedShadow) = ...
```

### 三种构造函数对比

| 类型 | 位置 | 特点 | 何时用 |
|------|------|------|--------|
| **Inner constructor** | `struct` 内部 | 调用 `new()` 创建对象，可做验证/转换 | **最少使用**，只在需要强制不变量时 |
| **Outer constructor** | `struct` 外部 | 调用 inner constructor 的便利包装，不能访问 `new()` | 提供默认值、类型转换 |
| **普通方法** | `struct` 外部 | 操作已有实例 | 所有非构造逻辑 |

### 官方最佳实践

尽量少写 inner constructor——只做必要的参数校验和不变量强制。便利构造（默认值、类型转换等）写成 outer constructor。

```julia
struct OrderedPair
    x::Real
    y::Real
    # inner: 仅做强制校验
    OrderedPair(x, y) = x > y ? error("out of order") : new(x, y)
end

# outer: 便利构造
OrderedPair(x) = OrderedPair(x, x)       # 单参数
OrderedPair() = OrderedPair(0.0, 0.0)    # 默认值
```

## 参数化 struct 签名与派发

### 参数化 struct 的三种签名写法

```julia
struct RandomGroup{N}
    ensemble::String
    M::Int
end
```

| 签名 | 作用 | 适用场景 |
|------|------|----------|
| `f(g::RandomGroup)` | 接受任意 N | 通用处理，不需要知道 N 的值 |
| `f(g::RandomGroup{N}) where N` | 绑定 N 为变量 | 函数体内需要用 N 的值 |
| `f(g::RandomGroup{4})` | 只接受 N=4 的实例 | 仅处理特定维数的情况 |

```julia
function process(g::RandomGroup{N}) where N
    println("量子位数: $N")
    zeros(Int, ntuple(_ -> 2, N))
end
```

### 多重派发只能基于类型，不能基于值

Julia 的派发是编译时行为，String 字段的值只有运行时才能确定，**无法**用做派发条件：

```julia
# ❌ 不合法——String 是运行时值，不能在类型签名里约束
function process(g::RandomGroup{ensemble="Pauli"}) end

# 只能写成运行时分支
function process(g::RandomGroup)
    if g.ensemble == "Pauli"    # Pauli 逻辑
    elseif g.ensemble == "Clifford"   # Clifford 逻辑
    end
end
```

### 推荐方案：用类型参数替代字符串

把业务分支从运行时字符串**提升**为编译时类型，才能利用多重派发：

```julia
# 1. 定义抽象类型和具体子类型
abstract type AbstractEnsemble end
struct Pauli <: AbstractEnsemble end
struct Clifford <: AbstractEnsemble end

# 2. struct 用类型参数 E 替代字符串字段
struct RandomGroup{E<:AbstractEnsemble, N}
    ensemble::E    # 不再是 String，而是 Pauli() / Clifford() 实例
    M::Int
end

# 3. 现在可以根据 ensemble 类型派发 ✅
process(g::RandomGroup{Pauli}) = println("处理 Pauli 系综")
process(g::RandomGroup{Clifford}) = println("处理 Clifford 系综")
process(g::RandomGroup{Pauli, 4}) = println("4 量子位的 Pauli")
```

### 设计理念：从运行时值到编译时类型

| 方案 | 分支机制 | 何时决定 | 性能 |
|------|---------|---------|------|
| `ensemble::String` + `if-else` | 运行时条件判断 | 运行时 | 无法编译优化，不能派发 |
| 类型参数 `E` + 多重派发 | 编译时类型匹配 | 编译时 | 可内联特化，零开销 |

这种模式在 Julia 中很常见（如 `Val` 类型、traits 系统、`@generated` 函数），本质都属于**用类型来编码信息**的技巧。

## 要点

- Julia 与 Python/Java 不同：struct 内不能定义普通方法
- 唯一能放 struct 内的函数是 inner constructor（调用 `new()`）
- 官方推荐：inner 越少越好，只做校验；便利构造放 outer
- 多重派发基于**类型**，不能基于运行时字段的**值**
- 想派发就**把业务分支从 String 改成具体类型**，用类型参数 `E` 替代字段
- 这是 Julia 中常见的"值→类型提升"（value-to-type）设计模式
