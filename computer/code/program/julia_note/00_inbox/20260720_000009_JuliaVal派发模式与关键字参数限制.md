# Julia `Val` 编译时派发模式与关键字参数限制

**日期**: 2026-07-20 22:00
**分类**: 编程/Julia
**标签**: #Julia #多重派发 #Val #关键字参数

## 背景

查看 `purity.jl` 中 `compute_sem=Val(false)` 的用法时，发现 `Val{true/false}` 作为位置参数可以触发编译时派发，但作为关键字参数则不行。同时涉及了 `all(f, collection)` 的用法。

## 内容

### `all` 函数

Julia 内置，检查集合中**所有元素**是否满足条件：

```julia
# 检查 meas_indices 中每个子列表长度是否都为 2
is_pair = all(g -> length(g) == 2, meas_indices)
# 等价 Python: all(len(g) == 2 for g in meas_indices)
```

### `Val{T}` 的派发用法

`Val` 是一个用于将值"提升"到类型层面的工具类型，常用于编译期分支选择：

```julia
# 入口函数
function get_purity(meas_indices, counts; compute_sem=Val(false))
    is_pair = all(g -> length(g) == 2, meas_indices)
    # 位置参数 → 参与派发
    _get_purity(meas_indices, counts, Val(is_pair); compute_sem=compute_sem)
    #                                ^^^^^^^^^^^^^ 位置 Val 参数，可派发
    #                                                      ^^^^^^^^^^^^^^ 关键字参数，不派发
end

# 两个方法，根据不同 Val 参数派发
function _get_purity(meas_indices, counts, ::Val{true}; compute_sem=Val(false))
    # pair 情况
end

function _get_purity(meas_indices, counts, ::Val{false}; compute_sem=Val(false))
    # 非 pair 情况
end
```

### 关键字参数不参与多重派发

Julia 的派发系统仅对**位置参数**生效，关键字参数无论什么类型都不能用来区分方法：

```julia
# ❌ 下面两个方法在 Julia 中只能存在一个（会报重定义错误）
function f(x; flag::Val{true}) ... end
function f(x; flag::Val{false}) ... end
# ERROR: MethodError - 关键字参数不参与签名，两者签名冲突

# ✅ 改成位置参数就可以了
function f(x, ::Val{true}) ... end
function f(x, ::Val{false}) ... end
```

### 几种分支选择方案对比

| 方案 | 分支机制 | 何时决定 | 适用场景 |
|------|---------|---------|----------|
| `if-else` 运行时判断 | 条件分支 | 运行时 | 简单分支、分支逻辑复杂 |
| `Val` 作为位置参数 | 多重派发 | 编译期 | 需要高性能、零开销的分支 |
| `Val` 作为关键字参数 | **无法派发** | — | ❌ 不可行 |

### 用 `Val` 的正确姿势

```julia
# 推荐模式：入口保持关键字 API 友好，内部用 Val 位置参数派发
function compute(x, y; use_fast=Val(false))
    _compute(x, y, use_fast)    # 转成位置参数再派发
end

function _compute(x, y, ::Val{true})
    # fast path — 编译器可以完全特化
end

function _compute(x, y, ::Val{false})
    # slow path
end
```

## 要点

- `all(f, collection)` = Python 的 `all(f(x) for x in collection)`
- `Val{T}` 的作用：把值编码到类型中，让编译器根据类型参数派发
- 关键字参数**永远不能**用于多重派发（不参与方法签名区分）
- 正确模式：API 层用关键字，内部转成位置参数再派发
