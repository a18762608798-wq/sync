# Julia `_` 前缀：内部函数命名约定

**日期**: 2026-07-20 20:30
**分类**: 编程/Julia
**标签**: #Julia #命名约定 #编码风格

## 背景

在 QMeasPost 项目中看到大量以 `_` 开头的函数（如 `_z_expect_from_counts`、`_parse_param_block`），这是 Julia 社区用于标记内部/私有函数的一种命名风格。

## 内容

### 约定而非强制

Julia **没有语言级的访问控制**（没有 `private`/`public` 关键字），`_` 前缀是社区约定，表示"这是内部实现细节，用户不应直接调用"。

### 本项目的实际用例

```julia
# 内部辅助函数，以下划线开头
function _z_expect_from_counts(counts, z_string)
    ...
end

function _parse_param_block(p::AbstractDict)
    ...
end

function _pauli_expect(pauli_char, psi)
    ...
end

# 对外公开的函数通过 export 声明
export RandomMeasResult,
       load_randmeas_result,
       expect_shadow,
       shadow_state
```

### Julia 真正的"私有"机制

真正的访问控制通过**模块系统**实现：
- 显式 `export` 或 `public`（Julia 1.11+）的函数才对 `using` 可见
- 未 export 的函数虽然通过 `ModuleName.funcname` 仍可调用，但被视为内部实现

```julia
module QMeasPost
export public_func   # 公开 API

function public_func(x) ... end
function _internal_func(x) ... end   # 惯例"私有"
end
```

## 要点

- `_` 前缀是软约定，非语言强制（Python 风格的惯例）
- 真实隔离靠模块的 `export`/`public` 机制
- 以 `_` 开头的函数不在 API 承诺范围内，可能随时改动
